# AGENTS.md

## Current Repo Shape
- This directory is a Git repository; the initial MVP files may still be untracked until explicitly committed.
- Python FastAPI app managed with `uv`; dependencies live in `pyproject.toml` and `uv.lock`.
- Runtime entrypoint is `app.main:app`; config loading is in `app/config.py`.
- Account credentials can come from environment variables or optional `config.yaml`; both `.env` and `config.yaml` are gitignored because they contain secrets.

## Commands
- Install/sync dependencies: `uv sync`.
- Run tests: `uv run pytest`.
- Run locally: `uv run uvicorn app.main:app --host 127.0.0.1 --port 8080`.
- Validate Docker Compose config: `docker compose config`.
- Build Docker image after code/dependency/Dockerfile changes: `docker compose build`.
- Run with Docker: configure `.env`, then `docker compose up`. No `config.yaml` is required or mounted by default.
- After changing `.env`, recreate the service with `docker compose up -d icloud-cruncher`; no image rebuild is needed. If using an optional YAML mount and changing only `config.yaml`, `docker compose restart icloud-cruncher` is enough.
- The MCP container has a Docker health check for `/healthz`; use `docker compose ps` to see `healthy` or `unhealthy`.

## Project Scope
- This project provides authenticated iCloud Calendar, Mail, Contacts, optional Drive and optional Reminders access through MCP.
- The standalone shared-calendar proxy is outside this project. Do not add public calendar feeds, token routes or source-URL configuration.
- HTTP endpoints are `/healthz`, `/mcp` and `/mcp/`; other paths return `404`.

## Local Testing Notes
- For local YAML configuration, copy `config.example.yaml` to `config.yaml` and replace the placeholder account credentials. Exporting credentials as environment variables also works without a config file.
- Docker uses `.env`; `config.yaml` can be mounted explicitly with a Compose override if needed. Never paste real credentials into committed files.
- VS Code tasks are in `.vscode/tasks.json` for sync, local run, tests, and Docker compose.

## iCloud Read/Write MCP

- `app/result_schemas.py` publishes typed success/error unions for all 45 tools; validate successes without projecting away valid native fields or content. Invalid replies become `backend_protocol_error`, preserving individually validated IDs, confirmed write state and declared fields, never invalid objects, unknown malformed data or arbitrary diagnostics/content. Preserve unknown extensions/content on valid replies. `app/mcp_errors.py` adds a shared `error` object to every tool failure. Preserve existing valid native error fields; `error.write_status`/`operation` can describe a failed sub-step, while `overall_write_status` and `request_operation` describe the complete call. Unknown/partial/succeeded write states require inspection; `automatic_retry_allowed` is always false. Never render or log validator input/exception text. Inputs use strict JSON types, numeric bounds and mode/content-source relationships. Contacts offset bounds reflect the active configured catalogue cap.
- IMAP mutations journal acknowledged APPEND/COPY/STORE/UID EXPUNGE steps and preserve known IDs, rejected steps and uncertain acknowledgements. Connection loss during UID EXPUNGE leaves its result null/unknown, never false. Verify source UID existence before flag/move/delete. Invalidate both affected mailbox/header and full-message caches after any attempted write, including failure or uncertainty. No automatic replay, rollback or mailbox-wide expunge. `update_draft` and `move_email` carry destructive annotations. Rebuild/recreate Python/Drive after these API changes; live write/auth/approval tests remain opt-in.

- `app/tool_usage.py` adds tool-specific workflow prerequisites, result interpretation and safe failure/recovery guidance to every published description. Keep this catalogue exhaustive and aligned with actual backend behavior. Omitted fields, partial coverage and unknown write state never prove absence or success; mirror folder names never prove a provider, and submitted MIME headers never prove verified send-as identity.

- `app/tool_contracts.py` publishes per-parameter descriptions plus schema-derived types, defaults and enums for every tool and nested input object. Keep the catalogue complete when adding parameters and regenerate `docs/mcp-tools.md` with `uv run python -m app.tool_reference --output docs/mcp-tools.md`. Reject unknown top-level parameters; validation diagnostics must never include input values or validator exception text. Draft `body_format` is exactly `plain|html`; attachments use the strict `DraftAttachment` model. `mail_account_info` reads configuration only, exposes no credentials and cannot verify folder existence or the upstream provider of an IMAP mirror. Never infer provider from folder labels or sender name from a signature. Draft results describe the submitted MIME From header, not verified send-as permissions. Inspect mailbox state before retrying failed draft writes; replacement is non-atomic.

- Drive creation/upload/replace are implemented in `app/drive_writes.py`. Inputs are bounded UTF-8/base64 or already-issued private snapshots resolved in the common server; never accept local paths or external source URLs. Refresh permissions and complete raw name coverage before activation. Activate uploads under unique staging names, verify bytes, then rename with native etags. `replace_drive_file` requires `confirm=true` and `expected_version`; stage and verify bytes before moving the original to native Trash with its fresh etag, then rename the staging file with its etag. Replacement is non-atomic and changes the file ID. Preserve confirmed steps, created/reserved IDs and any uncertain step; never replay, force an etag conflict or roll back automatically. `original_in_trash=null` means unknown, not false. Signed download/content-host assets receive no account credentials; upload URLs on verified iCloud account-service hosts retain scoped cookies only. The explicit `RUN_LIVE_DRIVE_WRITE_TESTS=1` smoke may create a fresh folder and replace only the file created in that invocation; keep artifacts for inspection and never modify pre-existing files.
- MCP tool names remain stable. `app/mcp_groups.py` adds service titles and `_meta["de.theinloth.icloud/service"]`, with deterministic Calendar/Mail/Contacts/Drive/Reminders order. Preserve tool schemas/annotations and existing metadata; custom service labels do not imply client UI support.

- Optional Drive uses the private `drive` Compose profile, `DRIVE_MCP_URL=http://drive:8080/mcp` and a dedicated `DRIVE_MCP_TOKEN` of at least 32 characters. Reuse the Go Reminders login through the extended administrative `drive-export` CLI; the `drive-auth` service under profile `drive-admin` builds the paired Go checkout and mounts both session volumes. Stop Go before administrative operations. Discovery/export never starts password/2FA login or device notifications; `--approve-web-access` explicitly requests keys for `iclouddrive` and verifies root access. Go remains the sole master-session writer. Runtime Python reads a separate immutable atomic export from `drive-data`, mounted read-only and kept out of the main service. Do not restore the removed Python authenticator. Preserve host-only/domain/secure/expiry cookie scope and account-bound reference keys across exports. Verify Apple HTTPS targets; signed download assets receive no account cookies/headers/parameters. Reject shared items, app libraries and packages. File references carry an encrypted parent hint; refresh that folder before and after downloads, because the folder metadata endpoint rejects direct FILE IDs. Resolve legacy references through bounded fresh folder catalogues and never infer absence from incomplete lookup. Bound traversal, responses, files and deadlines; preserve incomplete coverage and check metadata plus full-content versions. Mail/Drive share a 64-entry/30-MB/15-minute MCP snapshot store in separate namespaces, absent from resources/list and public routes. Drive never enters the mail-only semantic index. Never log file/account details, URLs, cookies or credentials. Outages must not block other backends. No live writes/new auth/device approval unless explicitly requested.
- iCloud Contacts use async CardDAV in `app/contacts.py` with typed tools in `app/contacts_tools.py`. Optional `CARDDAV_*` credentials fall back to shared `ICLOUD_*` credentials. Discover principals, address-book homes and collections through DAV; validate HTTPS targets and redirects before sending credentials. Only configured hosts and standard iCloud Contacts partition hosts may receive them. IDs are stable account/resource-scoped hashes resolved through fresh bounded catalogues; tool callers never supply remote URLs or vCards. Reads expose `coverage_complete` and `skipped_count`; incomplete results cannot establish absence. Contacts have no persistent cache or startup network calls. Creation refreshes permissions, generates a fresh UID and sends exactly one PUT with `If-None-Match: *`. Preserve confirmed and uncertain write state, IDs and UID on failures; never replay automatically. Readback failure must not erase confirmed creation. Never log names, contact fields, IDs, vCards, URLs or credentials. Contacts IDs must never substitute for Reminders participant IDs. Contact updates/deletion/photos/groups are not exposed.
- Native Reminders sections are `ListSection` records, separate from reminders. Section order and membership use bounded JSON metadata assets; preserve unknown properties, membership tombstones and native resolution-token replica IDs/counters with Apple's 2001 reference-date timestamps. Refresh list metadata and shared-list write permissions before atomic structure writes in the original owner zone. Reject cycles and cross-list parent/section/order anchors; never retry uncertain mutations. Tree views nest only matching reminders on the current page, preserve flat results and parent references, and explain display/priority/order symbols to the LLM. Local Python 1.4.0 builds with the Reminders 1.1.0 backend use `docker-compose.release.yml`; the base Compose file pins the published Go 1.1.0 commit.
- `batch_update_reminders` accepts a complete single-list target tree, including completed reminders and existing sections in their current order. New nodes omit IDs. Default `dry_run=true` only previews; applying uses one fresh Go MCP session and one total deadline with sequential, non-atomic writes. Validate all coverage, references and backend capabilities before writes. Preserve confirmed native results and created IDs on failure, identify any uncertain step, and never replay or roll back automatically. Batch writes do not delete, assign or change completion. The published 1.1.0 backend supports structural tools; optional UUID creation keys require the combined local backend or a newer release. Validate key support before any batch writes.
- Reminders participant discovery is read-only. `assign_reminder` requires exactly one of `participant_id` or `clear=true`; refresh accepted list membership and current-user write permissions in Go before writing. Use the exact participant ID from that reminder's list, never names or email addresses. Keep incoming shared-list operations in their original CloudKit database/owner zone. Never log participant names, contact details, IDs or assignment payloads. The live smoke test may discover participants but must never assign or clear a real reminder.
- Optional iCloud Reminders access uses the separate Go backend through `app/reminders.py` and typed tools in `app/reminders_tools.py`. Enable the `reminders` Compose profile and set `REMINDERS_MCP_URL=http://reminders:8080/mcp`; the Go build context is pinned to a commit in `Tooker/icloud-reminders-cli`. Go has no published port and owns its session/cache in `reminders-data`. `REMINDERS_MCP_TOKEN` is shared only between these services; never reuse Apple app-specific passwords as the bearer token. Python uses asynchronous MCP calls with a bounded total deadline, fresh sessions, no automatic write retries, preserved structured results, safe error messages and content-free logs. Backend outages must not block Python startup or Calendar/Mail. Reminders deletion requires explicit `confirm=true`. Authentication/ADP approval stays in the administrative Go CLI; stop Go before running it. The opt-in `RUN_LIVE_REMINDERS_TESTS=1` smoke test reads through Python only and must never call write/auth/approval tools.
- iCloud Calendar access uses CalDAV with an Apple Account email and app-specific password; never log or commit either credential.
- `app/icloud.py` is synchronous because `caldav` is blocking; MCP tools call it through worker threads.
- `list_events` expands recurring events into actual occurrences with `series_uid`, `recurrence_id`, and stable `occurrence_id`. `delete_event` requires explicit `scope=occurrence|series` plus the existing MCP `confirm=true`; occurrence deletion requires the original `recurrence_id`, adds a typed/timezone-preserving `EXDATE`, and removes only matching single-occurrence overrides. Preserve `THISANDFUTURE` range anchors and all later occurrences. Never fall back to a series delete. Cache expanded occurrences separately from UID-keyed master summaries.
- iCloud Mail access uses IMAP over SSL (`imap.mail.me.com:993`) with the same Apple Account/app-specific password by default; `app/imap.py` is synchronous and MCP tools call it through worker threads.
- MCP Streamable HTTP is mounted at `/mcp` and `/mcp/`; the app owns the MCP session-manager lifespan because it is mounted inside FastAPI.
- `list_calendars`, `list_events`, `get_event`, `list_mailboxes`, `search_emails`, `get_email`, and `get_email_attachment` are read-only. `get_email` supplies attachment IDs; `get_email_attachment` returns a complete native MCP file by default (up to 30 MB), extracts PDF/text with `format=text`, or returns bounded original byte chunks with `format=base64` through the same generation-checked full-message cache. Native files include an embedded binary resource and resource link; `resources/read` serves opaque-ID snapshots for up to 15 minutes with a 64-entry/30-MB memory bound. Keep snapshots out of `resources/list` and do not add public attachment download routes. Calendar creation/updates plus IMAP flag/move operations mutate iCloud; email deletion is destructive and requires `confirm=true`.
- OpenAI Secure MCP Tunnel is a separate `openai-tunnel` Compose service. It connects to `http://icloud-cruncher:8080/mcp` over the private Compose network and needs `CONTROL_PLANE_API_KEY` plus `CONTROL_PLANE_TUNNEL_ID`.
- Keep the write-capable MCP endpoint off the public internet. The default Compose binding is loopback-only.
- Normalized iCloud calendar lists and event reads use a persistent SQLite TTL cache when the service is configured. Docker stores it in the named `icloud-cache` volume; configure `ICLOUD_CACHE_PATH`, `ICLOUD_CACHE_TTL_SECONDS`, and `ICLOUD_CALENDARS_CACHE_TTL_SECONDS` as needed. iCloud remains the source of truth and successful calendar writes invalidate cached events.
- Calendar cache polling is enabled by `ICLOUD_CACHE_REFRESH_ENABLED` (default true), with `ICLOUD_CACHE_REFRESH_INTERVAL_SECONDS` (default 30; capped at half the event TTL). It warms the rolling default window at startup and up to eight recent unfiltered windows for one hour. Keep normal TTL/foreground fallback behavior, stop the worker on shutdown, and prevent in-flight refreshes from republishing entries invalidated by successful writes. Log only aggregate counts/status/timings and error classes.
- IMAP header searches use the same SQLite cache for up to `IMAP_EMAIL_CACHE_MAX_MESSAGES` (default 1000) messages from `IMAP_EMAIL_CACHE_DAYS` (default 100) days, refreshed by `IMAP_EMAIL_CACHE_TTL_SECONDS` (default 300). Mailbox listings use `IMAP_MAILBOX_CACHE_TTL_SECONDS` (default 1800). Full `.eml` messages are persisted as SQLite BLOBs with `IMAP_EMAIL_CONTENT_TTL_SECONDS` (default 86400); the background newest-to-oldest crawler is controlled by `IMAP_EMAIL_CACHE_CRAWL_ENABLED`, `IMAP_EMAIL_CACHE_CRAWL_BATCH_SIZE`, `IMAP_EMAIL_CACHE_CRAWL_INTERVAL_SECONDS`, and `IMAP_EMAIL_CACHE_MAX_MESSAGE_BYTES`. IMAP flag, move, and delete operations invalidate affected mailbox entries.
- When full-message snapshots exist, normal mail search reuses their immutable summaries without the old header-cache coverage cap. IMAP still determines current matching UIDs and refreshes flags/INTERNALDATE; fetch headers only for missing summaries. Never read `.eml` BLOBs for header searches, reuse mismatched generations, or treat partial SQLite snapshots as complete live coverage.
- MCP tool logs use `mcp_tool_start` and `mcp_tool_complete` with the tool name, outcome, duration, and safe result counts. Cache logs should expose read/write/invalidate status and counts without event contents, email headers, message bodies, mailbox contents, or credentials.
- MCP timing logs correlate nested `mcp_phase` spans with `call_id`, `span_id`, and `parent_span`; durations include child spans. Log phase names/outcomes/timings only, never arguments, SQL parameters, remote URLs, result contents or exception text. Keep detailed spans limited to active MCP requests.
- Optional semantic mail/PDF search uses existing account-scoped SQLite `.eml` BLOBs only; it never fetches IMAP or indexes calendar entries. `MAIL_SEARCH_ENABLED=true` plus `OPENAI_API_KEY` enables it; default model is `text-embedding-3-large`. Qdrant runs privately under the Compose `search` profile with no published ports and the `qdrant-storage` volume.
- Background embeddings use the OpenAI Batch API by default (`MAIL_SEARCH_EMBEDDING_MODE=batch`), with durable batch IDs/input hashes, partial-result reuse and remote file cleanup. Queries use immediate embeddings. Do not log batch inputs/output lines, queries, headers or credentials. `email_search_index_status` exposes only safe progress.
- Derived vectors and index state live in SQLite. Index identities include the account, model, dimensions and extraction version. Suppress matches whose source is invalidated or whose UIDVALIDITY changes; preserve `expected_uid_validity` in source retrieval references and reject mismatches before reading a reused UID.
